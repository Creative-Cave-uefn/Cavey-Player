# Cavey Mix — аудиодвижок DJ-режима

Нативная библиотека (C++17) и её Dart-обёртка. Две деки сводятся в одном аудиопотоке,
поэтому старт деки, автоматизации громкости, EQ, фильтра и темпа точны до сэмпла.
ТЗ на DJ-режим — в общем документе проекта; это этап 1 («движок»).

## Что умеет сейчас

- Две деки, вывод через miniaudio (WASAPI / CoreAudio / ALSA и др.).
- Декодирование MP3, FLAC, WAV — встроенными декодерами miniaudio; M4A/AAC, Opus, Ogg и прочее — через внешний ffmpeg
  (`cm_set_ffmpeg`): он запускается отдельным процессом и отдаёт сырой звук на родной частоте, перемотка — перезапуском
  с `-ss`. Задержку кодеров (AAC priming, Opus pre-skip) ffmpeg убирает сам. Приложение берёт ffmpeg из своей папки
  инструментов и докачивает его при необходимости.
- Приведение частоты файла к частоте устройства ресемплером Rubber Band (качество Best), без сдвига событий.
- Тайм-стретч Rubber Band R3 (Finer) с сохранением тона. Пока темп деки 1.0, звук идёт напрямую, бит-в-бит;
  тайм-стретч включается заранее, до начала изменения темпа, и подменяет прямой звук сшивкой 256 сэмплов.
- На деке: фейдер, выравнивание громкости (trim), 3-полосный изолятор (Линквиц — Райли 24 дБ/окт, кроссоверы 200 Гц и 2,5 кГц,
  полоса гасится полностью), фильтр на одной ручке (ФНЧ/ФВЧ с резонансом).
- Автоматизации любого параметра по «часам» движка, кривые: линейная, равной мощности (вход/выход), S-образная, ступенька.
- Точный старт и остановка деки по часам; микрозатухания против щелчков при паузе и перемотке.
- Эхо на деке (посыл до фейдера: хвост звучит и после остановки деки), задержка до 2 с, в петле ФВЧ 300 Гц и ФНЧ 5 кГц.
- Реверберация на деке (Freeverb, посыл до фейдера, срез ниже 250 Гц на входе), хвост — после остановки деки.
- Петля `cm_loop`: участок трека запоминается, пока дека его проигрывает, и повторяется бит-в-бит (и под
  тайм-стретчем); снятие петли — дека доигрывает проход и идёт дальше по треку.
- Торможение пластинки `cm_brake_at`: скорость и высота падают до нуля (кубическая интерполяция), затем дека встаёт.
- Лимитер мастера с упреждением 5 мс, потолок −1 дБFS.
- Офлайн-режим (`cm_create(rate, 1)` + `cm_render`) — для тестов и будущего рендера переходов в файл.

## Анализ треков (этап 2)

`cm_analyzer_create` / `cm_analyze_file` (`src/analysis.cpp`) — профиль трека v2 в JSON (ТЗ, раздел 3.3):

- **Доли и даунбиты** — нейросеть Beat This! (JKU Linz, ISMIR 2024, MIT) через ONNX Runtime. Конвейер повторяет
  эталон: моно 22 050 Гц → лог-мел (ONNX-модель `mel_spectrogram.onnx`, окнами) → нейросеть кусками по 30 с →
  пики логитов → даунбиты к ближайшей доле. ONNX Runtime подгружается во время работы (`LoadLibrary`/`dlopen`) —
  для сборки не нужен; входы и выходы модели берутся из неё самой.
- **Вокал** (`cm_analyzer_set_vocals`, необязательно) — модель Spleeter 2stems «vocals» (Deezer, MIT; ONNX-выгрузка
  sherpa-onnx, Apache-2.0, fp16, 19,7 МБ): модули STFT обоих каналов 44,1 кГц идут в модель кусками по 512 кадров
  прямо из декодера, по кадрам считается энергия голоса; в профиле `vocals` — доля голоса по тактам (кадр «с голосом»,
  если голос — больше 40 % его энергии и не тише 12 дБ от громких мест трека). На тесте (ударные + песня с 20-й
  секунды) голос найден в 23 тактах песни из 25 и ни в одном из 33 без неё; ~5 с на 2 минуты трека на двух ядрах.
- **Сетка темпа** — затравка по самой длинной цепочке ударов с шагом в долю (нейросеть иногда отмечает восьмые
  в интро — они в сетку не попадают), затем МНК по всему треку с сужающимся допуском, признак плавающего темпа; фаза уточняется по атакам
  звука с шагом 3 мс (нейросеть даёт шаг 20 мс).
- **Размер и первая сильная доля** — по даунбитам.
- **Громкость** — EBU R128 (BS.1770-4: K-фильтр, блоки 400 мс, пороги −70 и −10 LU), **истинный пик** — 4× передискретизация.
- **Тональность** — хромаграмма по высотной значимости (4 гармоники к основному тону) и профили Крумхансла — Кесслера; ключ Camelot.
- **Тишина** в начале и конце, **энергия** 1–10 по тактам, **границы фраз** (каждые 8 тактов, сила по смене громкости
  и гармонии), **секции** и **точки входа/выхода микса**.

Тесты (`cave_mix_analysis_tests`, последний прогон на Linux и в Windows-сборке под Wine с onnxruntime.dll 1.20.1):

| Тест | Результат |
| --- | --- |
| Доли и даунбиты против эталонной Python-реализации JKU (малая модель, 156 с джаза) | F-мера 0,996 / 0,997 при окне ±70 мс |
| EBU Tech 3341: синус 1 кГц −23 и −33 дБFS | −23,00 и −33,00 LUFS |
| Тональность: каденции Am, C, E, F#m | все четыре верно (Camelot 8A, 8B, 12B, 11A) |
| Синтетический бит 124 BPM, 4/4 | 124,000 BPM, фаза доли и такта точнее 3,1 мс |

Скорость: на этой тестовой машине (2 слабых ядра) нейросеть считает 156 с звука за ~8 с; Rust-порт эталона — за 6,4 с
на той же машине. На обычном ПК с 8+ ядрами — в разы быстрее.

## Автомикс (этап 3)

`cm_automix(e, from, to, profileA, profileB, options)` (`src/automix.cpp`) по двум профилям выбирает технику, точку
выхода из A (граница фразы), точку входа в B и длину, подгоняет темп B под A (с учётом кратности ×2/½) и ставит всё
в расписание движка по его часам. Возвращает план в JSON (техника, такты, точки, темп, часы начала и конца, причина
выбора). `cm_automix_cancel` снимает расписание и возвращает громкости.

| Техника | Что делает |
| --- | --- |
| T1 бас-свап | B входит без низа, низ меняется на сильной доле посередине, A уходит; 8/16/32 такта |
| T2 фильтр | A уходит в ФВЧ, B выходит из ФНЧ, низ меняется посередине; 8/16 тактов |
| T3 эхо-аут | A обрывается на конце фразы, хвост эха в долю, B стартует на следующую сильную долю A |
| T4 склейка | жёсткий переход на сильной доле, B — сразу с дропа |
| T5 петля | короткое аутро: последние 4 такта A крутятся петлёй, пока идёт бас-свап на 16 тактов |
| T7 торможение | A «останавливается пластинкой» за две доли, B входит точно на сильную долю |
| T8 реверб-аут | последний такт A уходит в реверберацию, сухой A обрывается на доле, хвост тянется поверх входа B |
| T11 плавный | равномощностный кроссфейд, когда сетки нет или темпы несовместимы |

После перехода темп B за 8 тактов плавно возвращается к родному. Если у обоих треков размечен вокал, планировщик
не допускает наложения голосов: вариант (точка выхода A, точка входа B, длина), где в среднем по тактам перехода
поют оба (больше 0,15), отбрасывается; плавный переход при наложении сжимается до такта. Выбор техники — по совместимости темпа и
тональности (Camelot), энергии и стилю, со случайностью по зерну (`seed`), без повтора предыдущей (`prev`).

Порядок треков (`cm_rank_next`, идея из Adaptive AutoDJ): из ближайших разобранных треков выбирается тот, что
лучше сводится с играющим (темп с учётом ×2/½, Camelot, энергия конца и начала, точки сведения, громкость) и подходит
характеру сета (без повторов исполнителя, энергия ровно / вверх / вниз); лучший путь ищется на 3 трека вперёд.
Плеер переставляет очередь только при «Вперемешку» и в волне, не трогая то, что человек поставил сам.

Тесты (`cave_mix_automix_tests`): два синтетических трека (124 BPM Am и 128 BPM C, разведены по каналам) проходят
анализ нейросетью, затем каждая техника играется офлайн. Замер на дорожках из щелчков: доли A и B в перекрытии
совпадают в среднем до 0,1–0,7 мс (худшая 3 мс — групповая задержка фильтра в T2), B встаёт на сетку A точнее 3 мс,
абсолютная ошибка сетки анализа ~6 мс. Уровень в переходе не проваливается глубже −5,5 дБ, пик под −1 дБFS,
недогрузок нет. Прогон на Linux (в т. ч. под ASan) и Windows-сборки под Wine. Демо: `demo_T*.wav` в рабочей папке.

Чего пока нет (следующие этапы ТЗ): полная модель Beat This! и All-In-One
(глубокий анализ); подключение автомикса в плеере (Dart).

## Устройство

```
API (любой поток) ──команды без блокировок──▶ аудиопоток ──seqlock──▶ cm_get_state
                                                  │
поток декодера деки ──блоки по 1024 кадра──▶ кольцо деки ─▶ [тайм-стретч] ─▶ trim·фейдер ─▶ EQ ─▶ фильтр ─┐
                                                                                                           ├─▶ лимитер ─▶ выход
                                                                       вторая дека (то же самое) ──────────┘
```

Файлы:
- `src/cave_mix.h` — C API (его же вызывает Dart);
- `src/engine.cpp` — поток декодера, деки, движок, C API;
- `src/readers.cpp` — источники звука: miniaudio и ffmpeg (запуск процесса на Windows и POSIX);
- `src/analysis.cpp` — анализ треков (Beat This! через ONNX Runtime, сетка, громкость, тональность, фразы);
- `src/tests/analysis_tests.cpp` — тесты анализа (нужны onnxruntime и модели, см. начало файла);
- `src/dsp.h` — фильтры, изолятор, сглаживание, лимитер;
- `src/spsc.h` — очередь без блокировок;
- `src/tests/engine_tests.cpp` — нативные тесты;
- `lib/cave_mix.dart` — привязки `dart:ffi` и класс `MixEngine`;
- `windows/`, `linux/` — сборка плагина Flutter'ом.

## Сборка

Отдельно ничего собирать не нужно: `flutter build windows` сам собирает `cave_mix.dll` через CMake
и кладёт её рядом с `.exe` (нужен тот же Visual Studio с C++, что и для самого Flutter под Windows).

Нативные тесты (Linux/macOS, или Windows из «Developer Command Prompt»):

```
cmake -S packages/cave_mix/src -B build/cave_mix -DCM_BUILD_TESTS=ON -DCMAKE_BUILD_TYPE=Release
cmake --build build/cave_mix
build/cave_mix/cave_mix_tests <папка_для_временных_wav>
```

Что проверяют тесты (последний прогон на Linux, x86-64):

| Тест | Результат |
| --- | --- |
| Прямое воспроизведение и старт в заданный кадр | бит-в-бит, точно в кадр |
| Ресемплинг 44,1 → 48 кГц | события на месте с точностью до сэмпла |
| EQ: выключенный низ | 60 Гц: −41,9 дБ; 5 кГц: 0,0 дБ |
| Лимитер, две громкие деки | пик ровно −1 дБFS |
| Темп 1.0 → 1.05 → 1.0 (Rubber Band R3) | клики не дальше 2,5 мс от расчётных; после возврата к 1.0 снова бит-в-бит |
| Битматч 125 → 120 BPM, 20 с | расхождение долей двух дек ≤ 0,23 мс |
| Кроссфейд равной мощности | уровень −0,05…+0,15 дБ |
| Пауза, перемотка, конец трека, битый файл | без сбоев |
| M4A, Opus, Ogg через ffmpeg | клики и перемотка точны до 0,04 мс, длительность верная |

Тесты также проходят под AddressSanitizer и ThreadSanitizer.
