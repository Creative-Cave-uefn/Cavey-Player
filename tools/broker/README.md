# Брокер загрузки Cave Player

Маленький сервис на Google Apps Script. Он открывает сессии загрузки файлов **от имени владельца библиотеки**
(аккаунта с подпиской на 5 ТБ), поэтому все новые треки и обложки занимают место владельца, а не друзей.
Байты файла друг отправляет напрямую в Google; через брокер проходят только короткие запросы.

Кто загрузил файл, брокер записывает в свойство файла `cave_uploader` — адрес берётся из проверенного токена,
подделать его со стороны клиента нельзя.

## Установка (один раз, с аккаунта-владельца)

1. Откройте <https://script.google.com> под аккаунтом владельца библиотеки → **Новый проект**, назовите «Cave Broker».
2. Вставьте содержимое `Code.gs` вместо кода по умолчанию.
3. Слева **Services (Сервисы) → +** → добавьте **Drive API** (версия v3, идентификатор `Drive`).
4. **Project Settings → Script properties** → добавьте:
   | Ключ | Значение |
   |---|---|
   | `CLIENT_ID` | OAuth Client ID приложения Cave Player (тот же, что в приложении) |
   | `ROOT_ID` | ID папки «Cave Player» (из ссылки на папку) |
   | `OWNER_EMAIL` | (необязательно) почта владельца |
   | `MAX_BYTES` | (необязательно) предел размера файла, по умолчанию 524288000 |
   | `LOG_SHEET` | (необязательно) ID Google Таблицы для журнала: время, событие, почта, детали |
5. **Deploy → New deployment → Web app**: *Execute as* — **Me**, *Who has access* — **Anyone**.
   Разрешите доступ (скрипту нужны Диск и внешние запросы).
6. Скопируйте адрес `https://script.google.com/macros/s/…/exec`.
7. Положите его в `cave-data/config.json` в общей папке:

```json
{
  "broker": "https://script.google.com/macros/s/XXXX/exec",
  "minClientVersion": "0.0.0"
}
```

После обновления кода: **Deploy → Manage deployments → Edit → New version** (адрес сохранится).

## Проверка

Откройте адрес `/exec` в браузере: должно вернуться `{"ok":true,"service":"cave-broker",…}`.

## Что проверяет брокер

- токен выдан именно приложению Cave Player (`aud`/`azp` = `CLIENT_ID`) и почта подтверждена;
- человек — участник папки «Cave Player» (или владелец);
- папка назначения лежит внутри библиотеки;
- размер, расширение; запас свободного места у владельца;
- не больше 300 запросов `begin` в час на человека (альбом из 20 треков с обложками — около 40);
- удалить файл может только владелец или загрузивший (`cave_uploader`; у старых файлов — их владелец на Диске).

## Известное ограничение

Старые файлы (загруженные друзьями до брокера) принадлежат друзьям. Корзина чужого файла владельцу библиотеки
недоступна, если у него нет права `canTrash`; в этом случае брокер вернёт `not_owner`, а приложение удалит файл
через аккаунт загрузившего (как раньше).

## Перенос старых файлов на диск владельца (действие `adopt`, версия API 2)

Старые файлы друзей можно перенести владельцу библиотеки **без копирования**: id файла не меняется, поэтому плейлисты,
лайки, статистика и офлайн-копии остаются на месте. Google разрешает передать владение только текущему владельцу, поэтому:

1. Cavey друга (его токеном) назначает владельца библиотеки «ожидающим владельцем» своих файлов в общей папке;
2. `adopt` (работает от имени владельца библиотеки) принимает владение и записывает прежнего владельца в `cave_uploader`,
   так что «кто загрузил» и права на удаление остаются прежними. Время изменения файла сохраняется, теги заново не читаются.

**После обновления `Code.gs` скрипт нужно один раз заново развернуть**: Deploy → Manage deployments → Edit → New version.
Пока этого не сделано, Cavey у друзей покажет «брокер нужно обновить» и ничего не перенесёт.
Ограничения Google: работает для обычных аккаунтов и файлов в «Моём диске» (не в общих дисках).

## Ограничения и что проверить после установки

- Роль «Редактор» оставлена по решению владельца. Через Диск напрямую участник теоретически может создать файл в папке
  (он займёт его место) или отправить чужой файл в корзину — приложение так не делает, но технически Диск это разрешает.
  Если нужно жёстче, переведите участников в «Читатели» и оставьте запись только брокеру: тогда переименование и обложки
  придётся тоже пропускать через брокера.
- Проверьте на тестовом файле, что брокер (аккаунт владельца) может отправить в корзину файл, загруженный другом
  по-старому: если `canTrash` ложно, брокер вернёт `not_owner`, и такой файл по-прежнему удаляет сам загрузивший.
- Квота Apps Script: ~20 000 вызовов `UrlFetchApp` в сутки для обычного аккаунта. Один `begin` — 2 вызова
  (проверка токена + открытие сессии; проверка токена кэшируется на время жизни токена).
- Версия клиента: если в `config.json` поднять `minClientVersion`, старые версии Cavey перестанут загружать файлы
  и покажут просьбу обновиться (воспроизведение и остальное работают как раньше).
