# Intelligent DJ: локальный ритм, голос и акустическая проверка

Ветка `int/intelligent-dj-v2`, draft PR #16. Движок media_kit/mpv сохранён.
До Windows-сборки, проверки основных функций и прослушивания в main не сливать.

## Что реализовано

| Блок | Поведение и граница достоверности |
|---|---|
| Локальный ритм | Анализатор v3: окна 24 с/шаг 8 с, BPM, найденные атаки в исходном времени, поддержка пульса и остаточная ошибка в мс. Пропуски не заполняются выдуманными долями. Это DSP baseline, не обученный beat/downbeat detector. |
| Groove и атаки | Широкополосный/низкочастотный рисунок внутри доли, спектральные признаки в моменты атак. Разные groove ограничивают длинное синхронное наложение, не исключая сам трек. |
| Переменный темп | Можно использовать устойчивую локальную область, даже если общая сетка нестабильна. Окно обязано покрывать всё наложение обеих дек с учётом rate. Размер такта остаётся неизвестным. |
| Структура | Двусторонняя novelty и непоследовательные повторы дескрипторов/recurrence cluster. Функция секции `unknown`: куплет/припев/drop не распознаются. |
| Голос | Опциональный локальный YAMNet с закреплённым SHA-256; CPU, окна 975 мс/шаг 480 мс. Сравниваются именно одновременные голосовые участки с учётом cue и rate. |
| Достоверность голоса | YAMNet — broad audio-event baseline, не откалиброванный polyphonic SVD. Низкие scores не доказывают инструментальность. Midrange V1 не подтверждает отсутствие голоса. |
| Длина наложения | Подтверждённый конфликт — максимум 2 с. Без независимых данных — максимум 4 с; с моделью без сильного совпадающего риска — максимум 8 с. Проверенные внешние метки могут разрешить больше. Legacy-анализ не разрешает длинный blend только по слабому proxy. |
| EQ handover | В Adaptive beat blend с bass swap бас, середина и верх передаются отдельно. Полосы только ослабляют. Центральная часть огибающей сохраняет совместное звучание. Это не source separation. |
| Владение фильтрами | Именованный фильтр каждой деки, сериализация/объединение команд, удаление своего эффекта при завершении/отмене. Вся цепочка af не заменяется. Проверяются наличие фильтра и native error log; это не проверка PCM-выхода. |
| Acoustic preflight | FFmpeg рендерит выбранное наложение из уже кэшированных оригиналов. Проверяет полноту, nonfinite, тишину и true peak ≤ −1 dBTP. Учитывает выравнивание громкости; оценка консервативна при mpv volume clamp. Скрытого limiter нет. |
| Fallback | Нет оригиналов в AudioCache, пропущена cue, таймаут/плохой рендер или недоступный EQ — обычный AutoMix. Проверка не скачивает дополнительные файлы. Потоковое воспроизведение сохраняется. |
| Выбор | До 5 треков, beam H=3/W=6, история 8 треков, характер сета. Очередь пользователя, ручные пары и джем имеют прежний приоритет. BPM/Camelot не исключают треки. |
| Cut | По умолчанию выключен; тесты требуют явного opt-in. Если разрешение было сохранено вручную раньше, его можно выключить в настройках анализа. |
| Диагностика | Decision/preflight/execution связаны decisionId; есть cue, rate, компоненты оценки, EQ, причины fallback и транспортная фаза. В журнал не пишутся OAuth/URL/аудио. |

Схема TrackFeatures остаётся 1; `sx`, `rt`, `va` — необязательные версионированные
расширения. Анализатор повышен до 3. Старые записи не удаляются и работают, пока
фон пересчитывает их. Повреждённые расширения не делают старые данные нечитаемыми.

## Windows: сборка и публикация в тестовый канал

Для пакета с моделью один раз установите Python 3.11, если его нет:

```powershell
winget install --id Python.Python.3.11 -e
```

Откройте новое окно PowerShell. Выберите папку **исходников**, например
`C:\Users\ilya-\source\Cavey-Player`, а не папку установленного приложения:

```powershell
$repo = Read-Host 'Полный путь к папке Cavey-Player с исходниками'
Set-Location -LiteralPath $repo

git status --short
git switch int/intelligent-dj-v2
if ($LASTEXITCODE -ne 0) { throw 'Не удалось переключить ветку' }
git pull --ff-only
if ($LASTEXITCODE -ne 0) { throw 'Не удалось обновить ветку' }

powershell -NoProfile -ExecutionPolicy Bypass -File tools\local-test-build.ps1 -WithAudioModels -Publish
```

Нужны прежние зависимости Windows-сборки: Flutter 3.27.4, VS C++ desktop tools,
GitHub CLI и Inno Setup. Подробно: [LOCAL_BUILD.md](LOCAL_BUILD.md).

Скрипт выполняет анализ, все Flutter-тесты, Windows release build, упаковку модели и
self-test упакованного exe, установщик и portable. Только после успеха публикует
**тестовый prerelease** в `Creative-Cave-uefn/cave-player-releases` с verification.md/json
и SHA-256. Workflow не используется. Прослушивание не помечается успешным автоматически.

Python нужен на машине сборки. Для прослушивания используется упакованный
`audio-intelligence/cave-intelligence.exe` и модель рядом с плеером. Сервер не нужен;
инференс не загружает веса и не отправляет аудио. Лицензии/происхождение:
[THIRD_PARTY.md](../tools/intelligence/THIRD_PARTY.md).
Без `-WithAudioModels` получается пакет без модели; это явно указывается в отчёте.
Старые файлы модели не включаются в такой пакет случайно.

## Проверка на музыке

1. Установите тестовый пакет и проверьте в настройках анализа наличие модели.
2. Выберите «Весь трек» → «Полный анализ очереди». Дождитесь счётчиков секций,
   локального ритма и модели голоса. Android читает результаты, но не считает их.
3. Сохраните тестовые треки для автономного воспроизведения: preflight требует оба
   оригинала в AudioCache. Без них ожидается явный fallback AutoMix.
4. Проверьте «Свести сейчас» в разных частях песни и автоматический переход.
   Оценивайте устойчивое совместное звучание, groove и передачу частот.
5. Проверьте pause/seek/next, повторные нажатия, очередь пользователя и ручные деки.
6. Отдельно проверьте Drive, AudioCache, поток без кэша, «Мою волну», восстановление
   очереди и настроек после перезапуска.
7. Экспортируйте DJ-диагностику. Для плохой пары сохраните decisionId и SHA сборки;
   повторите её трижды. Транспортные часы не заменяют захват Windows-аудиовыхода.

Особенно нужны: одинаковый BPM/разные барабаны; live с устойчивым локальным окном;
два одновременных вокала и голоса в разные моменты; контрастные жанры/BPM; эмбиент;
громкий мастер; неполный анализ; медленный Drive и отсутствующий кэш.

## Слепой набор AutoMix / Adaptive на одинаковых треках

Нужны Python и FFmpeg. Подготовка по экспортированному журналу:

```powershell
python tools\dj_benchmark.py --journal 'D:\DJ\transitions.jsonl' --list
python tools\dj_benchmark.py --journal 'D:\DJ\transitions.jsonl' --template 'D:\DJ\tracks.json'
```

В tracks.json укажите локальные оригиналы по их ID, затем:

```powershell
python tools\dj_benchmark.py --journal 'D:\DJ\transitions.jsonl' --files 'D:\DJ\tracks.json' --all --limit 12 --out 'D:\DJ\second-pass' --blind-seed 17
```

Если FFmpeg не в PATH, добавьте `--ffmpeg 'ПУТЬ\ffmpeg.exe'`.
В каждой папке: A.wav, B.wav, report.json, ratings.csv, blind-key.json.
В корне: set.json, playlist.m3u, listening-sheet.csv. Ключ открывается после оценок.
`--all` исключает ручные нажатия и повторы, сравнивает одинаковые оригиналы.
Сохраняются их SHA, sample/true peak, LUFS, nonfinite/overs и соседний скачок отсчёта;
последний не является доказательством щелчка.

Рендер воспроизводит **предложенный план**, в том числе отклонённый preflight,
чтобы можно было оценить причину. Это не означает, что план исполнил плеер.
Preflight/execution присоединяются по decisionId, когда есть в журнале. Версия EQ
и нормализация учитываются. Runtime clock drift, сеть, rate correction, сбой
native-фильтра и последующий возврат скорости не воспроизводятся.
Хороший offline A/B не доказывает качество фактического mpv-выхода.

## Что ещё не закрыто по расширенному ТЗ

- Обученный beat/downbeat/meter для сложного live: текущие локальные атаки — DSP baseline.
- Откалиброванный music SVD, activity 10–20 Hz и проверка голосового stem.
- Семантическая структура verse/chorus/drop, foundation music embeddings/mood.
- Source separation и техники с независимым управлением stems.
- Ранжирование нескольких отрендеренных планов: сейчас поиск по признакам выбирает
  один, после чего он проверяется; при отказе используется AutoMix.
- Windows output PCM, музыкальные слепые оценки и проверка регрессий основных функций.
- Общий sample clock/native renderer отложен: по заданию движок пока не заменяется.
