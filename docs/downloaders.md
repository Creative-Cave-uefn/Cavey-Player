# Источники загрузки Cavey

## Режимы

- **YouTube** — поиск по тексту, ссылки YouTube, Spotify, Deezer, Apple Music и Яндекс Музыки (у последних четырёх берём метаданные, не защищённые аудиопотоки).
- **Soulseek** — Sockseek с локальным отдельным аккаунтом Soulseek.
- **Bandcamp** — прямая ссылка на трек или альбом, только доступный аудиопоток.
- **Deezer** — локальный адаптер к deezer-downloader 2.15.0. Треки, альбомы и плейлисты Deezer; поиск по строгому «Исполнитель - Название».
- **Полный поиск** — для каждого трека Deezer → Soulseek → YouTube → Bandcamp, следующий источник вызывается только при неудаче предыдущего. Для текстового поиска требуется «Исполнитель - Название». Публичный поиск Bandcamp best-effort и может не находить записи.

В полном режиме альбомы и доступные плейлисты обрабатываются с **3 параллельными воркерами**. Каждый трек ищется в порядке источников (без дублирующих одновременных скачиваний). Учитывается уже существующая музыка в библиотеке. Плейлисты Spotify могут быть ограничены количеством треков в доступной без авторизации веб-странице.

## Установка Deezer

Откройте Cavey → Аккаунты → Загрузчик музыки → **Установить Deezer**. Требуется Python 3.10+ на Windows. Отдельное окружение создаётся в локальной папке инструментов, пакет скачивается с PyPI. После установки нажмите **Открыть конфиг Deezer** и укажите свой ARL в локальном `deezer_auth.ini`. Ни пароль, ни ARL не записываются в репозиторий и не синхронизируются в Google Drive.

Автоматическая инициализация при первом создании конфига возможна через переменные окружения, выставленные **на компьютере пользователя**: `CAVE_DEEZER_ARL`, `CAVE_SOULSEEK_USERNAME`, `CAVE_SOULSEEK_PASSWORD`. Они не перезаписывают существующий конфиг. В приложении не реализовано извлечение браузерных cookies или паролей из чужих процессов.

Deezer-запросы обрабатывает локальный Python-мост, адаптированный из выделенного модуля. Зависимости и учётные данные не входят в сборку программы. Soulseek работает через отдельный установленный Sockseek.

## Ограничения и безопасность

Spotify и Apple Music в этом коде используются только как **источники метаданных**: прямой загрузки их защищённого каталога или обхода DRM нет. Поиск Bandcamp использует публичные страницы и не выдаёт оплаченные оригиналы. Фактическая доступность треков зависит от аккаунта, сети, прав на записи и изменений внешних сервисов.

Сессионный ARL и пароль Soulseek нужно хранить локально. Если они были опубликованы, обновите оба. Не загружайте конфиги в Git, не включайте их в логи/архивы.

Текущий Cavey-Player использует свой `lib/core/dl/service.dart`. Отдельный репозиторий Cavey-Downloader имеет совместимые идентификаторы режимов, но автоматическая загрузка **его исполняемого файла** в текущем плеере пока не подключена. Плеер сам устанавливает Python-зависимость Deezer; не следует путать это с доставкой exe-модуля.

Перед релизом: `flutter analyze`, `flutter test`, Windows-сборка; затем ручной тест на разрешённых для скачивания аудиозаписях.

## Значения авторизации по умолчанию для всех установок

Репозиторий **не содержит открытым текстом** логин, пароль или ARL. Их можно один раз задать в **GitHub → Settings → Secrets and variables → Actions → Repository secrets** для `Creative-Cave-uefn/Cavey-Player`:

- `CAVE_DEEZER_ARL` — Deezer ARL своей учётной записи.
- `CAVE_SOULSEEK_USERNAME` — имя учётной записи Soulseek.
- `CAVE_SOULSEEK_PASSWORD` — пароль Soulseek.

GitHub Actions передаёт эти значения в `--dart-define` во время сборки. Новая Windows-сборка получает их **внутрь EXE**, а на первом запуске Cavey автоматически создаёт `tools/deezer_auth.ini` и `tools/sockseek.conf`. Если конфиги существуют с заглушками, они обновляются. Пользовательские значения не перезаписываются. Отдельный исполняемый `Cavey-Downloader` собирается в другом репозитории; если его будут распространять отдельно, те же три Actions Secrets нужно выставить и там.

**ВНИМАНИЕ:** это удобство установки, **не защищённое хранилище**. Любой, кто получит EXE, потенциально может извлечь учётные данные. Совместное использование сеансов может привести к ограничениям или блокировке аккаунтов. Если Secrets не заполнены, сборка не получает глобальные значения и создаёт обычные заглушки. Для обновления общих данных требуется новая сборка и локальная замена старых значений (автоматическая ротация существующих пользовательских конфигов не предусмотрена).

## Универсальные ссылки и устойчивый YouTube-поиск

Поддержаны два типа ввода:

- **Каталоги:** Spotify, Deezer, Apple Music и Яндекс Музыка. Из них получаются метаданные, затем аудио ищется в активном источнике. Полный поиск пробует Deezer → Soulseek → YouTube → Bandcamp.
- **Прямые страницы:** YouTube, Bandcamp, SoundCloud, Audiomack, Mixcloud и Internet Archive. Если на странице доступен аудиопоток, его извлекает yt-dlp. Неизвестные веб-адреса и локальные URL не передаются экстрактору, чтобы не создавать уязвимостей и не обещать поддержку любых сайтов.

Режим «Полный поиск» различает два случая: каталоги проходят fallback для каждого трека; прямые страницы отправляются в соответствующий экстрактор без угадывания трека на других платформах.

Надёжность YouTube: поисковые запросы Official Audio, обычный, Audio, Topic и Lyrics; не больше двух одновременных поисков; до трёх попыток для временных сетевых ошибок с задержками. yt-dlp получает пять сетевых попыток, пять попыток сегментов, три попытки извлечения, а Deno запускает EJS через параметр --remote-components ejs:npm. Некоторые ошибки 403, возрастные ограничения и ограничения правообладателей неустранимы повторами.

Для выпуска проверить flutter analyze, flutter test и Windows CI. Использовать для тестирования аудио, доступное для законного скачивания.

## Перекачать трек и обложки Deezer

В списке треков нажмите ПКМ → **«Перекачать трек…»**. После подтверждения Cavey ставит задание в ту же очередь загрузчика и ищет аудио через выбранный источник; для режима «Полный поиск» используется цепочка Deezer → Soulseek → YouTube → Bandcamp. Новая запись приводится FFmpeg к формату исходного файла и после подготовки заменяет содержимое **того же файла Google Drive**, без создания нового ID. Лайки, плейлисты, ссылки и правки метаданных сохраняются. Требуются права на запись в этот файл. Старые байты в Диске не удаляются до завершения подготовки новой версии; после успешной замены восстановление возможно только из истории версий Google Диска, если она доступна. Кэш аудио сбрасывается.

В ПКМ → **«Изменить метаданные…»** автоматически выполняется запрос обложки через открытый каталог Deezer. Отдельная кнопка «Найти обложку в Deezer» позволяет повторить поиск после исправления названия или исполнителя. Обложка выбирается только при точном совпадении исполнителя и названия альбома/трека и если её исходное разрешение выше текущего. Выбор можно отменить; на Google Диск изображение загружается только после «Сохранить». Официальная Deezer API здесь используется только для общедоступных метаданных и изображений, без ARL.

Известные ограничения: повторная загрузка зависит от доступности записи у источника, прав доступа Google Диска и установленных внешних инструментов. Не всякая музыка доступна для повторного скачивания. Перекодирование в формат исходного файла не повышает качество источника.
