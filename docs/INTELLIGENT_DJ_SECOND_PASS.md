# Intelligent DJ: второй прогон

## Что изменилось

1. Анализатор v2 сохраняет локальные непересекающиеся окна по 4 секунды: MFCC,
   хрому, спектральный центроид, энергию, долю баса, плотность атак, долю звучащего
   материала и пиковый уровень декодированного mono. Последний не является stereo true peak.
2. По изменениям дескрипторов отмечаются вероятные границы. Это не распознавание
   куплетов/припевов/drop и не нейросетевая семантика.
3. Планировщик совместно выбирает выход, вход, длину и технику: beat blend,
   короткий crossfade, структурный cut, атмосферное наложение для слабых атак.
   Рассматриваются до 8 выходов и 6 входов; результаты пар кэшируются в beam search.
   Для «Свести сейчас» оценивается текущая область исходящего трека, а не его конец.
4. Настройка характера сета: ровно / нарастание / спокойнее / контрасты.
   Учитываются последние 8 реально запущенных треков, повторения исполнителя,
   жанра и техники. Энергетическая траектория использует физическую громкость;
   это не модель настроения, агрессии или valence.
5. JSONL-журнал различает decision и execution. В decision есть компоненты оценки,
   альтернативы, маршрут, версия источника и обычный AutoMix baseline той же пары.
   В execution — фактические транспортные позиции, скорости, длительность подготовки,
   момент bass swap, средняя/медианная/p95 фазовая ошибка и причина завершения.
   Эти часы не доказывают точность/качество выходного PCM.
6. Экспорт журнала и полный анализ ближайшей очереди доступны в настройках анализа звука.
7. Добавлен отдельный Python/FFmpeg A/B-инструмент для воспроизводимого прослушивания
   выбранного плана и измерения отрендеренного PCM. Это не захват Windows playback.

## Совместимость и обновление

Схема TrackFeatures остаётся 1; секции — необязательное расширение `sx` с собственной
версией. Анализатор повышен до 2. Старые записи не удаляются и работают через прежнюю
оценку intro/outro, пока Windows в фоне не досчитает новые. Android может читать
готовые записи. Повреждённое расширение игнорируется без потери прежних признаков.

Секции округляются при записи; размер публикуемого shard ограничен бюджетом примерно
1 МиБ (одиночная запись, превышающая бюджет, передаётся отдельно). Старые immutable
шарды не перезаписываются. Это не вводит глобальный manifest/compaction облачной истории.

В настройках «Анализ звука» выберите «Весь трек» и нажмите «Полный анализ очереди».
Кнопка пересчитывает текущий и до пяти следующих треков; общий фоновый анализ остальных
продолжает действовать. Дождитесь роста счётчика «Секционный анализ».

## Вокал: граница готовности

**Автоматический обученный детектор голоса не поставляется.** Нужны отдельные веса,
проверка их условий и benchmark на нашей музыке. Midrange-кривая V1 остаётся эвристикой;
она не превращается в уверенную вероятность и не доказывает отсутствие вокала.
При неизвестном вокале или конфликте накладываемые области укорачиваются.

Предусмотрен валидируемый вход для ручной разметки или отдельно подготовленного
детектора: «Импорт вокальных меток» в настройках анализа. Файл JSON до 4 МиБ:

```json
{
  "version": 1,
  "tracks": [{
    "id": "TRACK_ID_FROM_JOURNAL",
    "revision": "EXACT_REVISION_FROM_JOURNAL",
    "source": "annotation",
    "segments": [
      {"startMs": 0, "endMs": 16000, "probability": 0.05, "confidence": 0.95},
      {"startMs": 16000, "endMs": 32000, "probability": 0.95, "confidence": 0.95}
    ]
  }]
}
```

Вместо annotation допускается `model:<точный checkpoint>`. Это только происхождение,
не сертификат качества модели. Интервалы должны быть отсортированы и не пересекаться.
Требуется текущая версия файла и готовые секции; весь пакет проверяется до изменения
индекса. Непокрытые интервалы остаются неизвестными. Для использования надёжного
вокального признака нужны >=90% покрытия области и confidence >=0.75. После замены
аудиофайла или принудительного перерасчёта разметку потребуется проверить/импортировать вновь.

Из корня исходников PowerShell:

```powershell
git pull --ff-only origin int/intelligent-dj-v2
if ($LASTEXITCODE -ne 0) { throw 'Ошибка обновления' }
powershell -NoProfile -ExecutionPolicy Bypass -File tools\local-test-build.ps1 -Publish
```

Скрипт выполняет analyze, все Flutter-тесты, Windows release build и упаковку.
Публикует установщик/portable и verification.md/json только после успеха, без workflow.
Установленная сборка — из ветки int/intelligent-dj-v2; main не меняется.

## Первый runtime-прогон

- 10–12 треков: электроника, вокальные пары, hip-hop, живые барабаны, эмбиент, контрастные жанры.
- Полностью разберите ближайшую очередь. Сначала проверьте AutoMix, затем Adaptive на тех же файлах.
- Проверьте авто-переход и «Свести сейчас» в начале/середине/конце трека.
- Повторите паузу, перемотку, next, перестановку очереди и закрытие окна во время подготовки/наложения.
- Повторите из кэша и потоком с Drive; отдельно проверьте «Мою волну», ручные пары, пользовательский следующий трек и джем.
- Убедитесь, что характер сета меняет решения, но не отменяет проверки риска.
- Сохраните `verification.md` и экспорт DJ-диагностики. Нет execution с completed —
  выбранный decision ещё не подтверждает, что именно он отыграл.

Журнал хранится локально в подкаталоге `dj` данных приложения: текущий файл и одна
предыдущая ротация, около 4 МиБ каждый. OAuth/URL потоков и само аудио в него не пишутся.
Экспорт содержит ID треков и версии файлов; названия путей к вашей музыке туда не добавляются.

## Слепой A/B на одном transition plan

Нужны Python 3.10+ и FFmpeg; это отдельный инструмент, плеер их через Python не запускает.
Экспортируйте журнал в удобную папку. Затем:

```powershell
python tools\dj_benchmark.py --journal "D:\DJ\cavey-dj-transitions.jsonl" --list
python tools\dj_benchmark.py --journal "D:\DJ\cavey-dj-transitions.jsonl" --template "D:\DJ\tracks.json"
```

В tracks.json замените заглушки на пути к соответствующим локальным оригиналам.
Для честного сравнения используйте одинаковые файлы и decision автоматического перехода,
а не ручного нажатия в середине песни. Номер decision указан в --list:

```powershell
python tools\dj_benchmark.py --journal "D:\DJ\cavey-dj-transitions.jsonl" --files "D:\DJ\tracks.json" --decision 0 --out "D:\DJ\pair01" --blind-seed 17
```

Если FFmpeg отсутствует в PATH, добавьте `--ffmpeg "ПУТЬ\ffmpeg.exe"`.
Получатся A.wav, B.wav, report.json, ratings.csv и blind-key.json.
Не открывайте ключ до оценивания timing/smoothness/vocal conflict/fit.
Отчёт содержит SHA-256 источников и рендеров, sample peak, true peak по FFmpeg ebur128,
LUFS, число nonfinite/over-full-scale samples и максимальный соседний скачок отсчёта.
Последний сам по себе не является детектором щелчков. Цель -1 dBTP отмечается отдельно;
инструмент не добавляет скрытый limiter и не гарантирует её достижение.

Ограничения рендера: воспроизводятся локальные cue/tempo/gain/bass-фильтры плана,
но не фактический clock drift, сетевые буферы, runtime phase correction или возврат
темпа после сведения. Предполагается выключенная нормализация и отсутствие ручных EQ.
Поэтому хороший A/B-рендер не доказывает, что две mpv-деки исполнили его так же.

## Инженерные проверки инструмента

```powershell
python -m unittest discover -s tools -p test_dj_benchmark.py -v
```

Тесты синтезируют собственные тоны, рендерят обе версии и проверяют измерение PCM.
Распределяемой музыкальной коллекции/чужих весов в репозитории нет.
